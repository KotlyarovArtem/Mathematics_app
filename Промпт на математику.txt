Ты — Senior Python-разработчик и UX/UI-дизайнер, специализирующийся на геймифицированных образовательных приложениях для детей.

Твоя задача — написать ПОЛНЫЙ, работоспособный и эстетичный код локального desktop-приложения на Python (PySide6) для детей 6–10 лет (1–4 классы). Приложение предназначено для проверки и развития навыков решения арифметических примеров.


###1. Краткое описание
    Desktop-приложение для проверки умений учеников начальных классов выполнять элементарные математические действия.
###2. Целевая аудитория
    Приложение для детей 6, 7, 8, 9, 10 лет.
###3. Функции приложения:
    3.1. Приложение должно локально запускаться в отдельном окне. Окно должно иметь современный детский Flat Design на базе QSS (пастельные тона: мятный, нежно-голубой, мягкий желтый, коралловый) с простыми анимациями, чтобы привлекало внимание ребенка. Ребенок должен выбрать персонажа-помощника перед началом сессии: фея "Динь", динозаврик "Лаки".  Шрифт должен легко читаемым, кнопки должны быть понятными.
    3.2. В окне приложения пользователь должен написать свое имя, какой возраст (сколько ему лет), которые сохранятся для всех следующих сессий и по которым должна будет вестись статистика правильных и неправильных ответов. Должна быть защита от некорректного ввода (блок ввода текста вместо чисел, валидация).
    3.3. Из выпадающего списка пользователь должен выбрать в каком классе он учится: 1 класс, 2 класс, 3 класс, 4 класс. При выборе класса должен учитываться возраст пользователя: если возраст 6 или 7 лет, то в выпадающем списке должен быть доступен 1 класс, если возраст 8 лет, то должны быть доступны 1 класс и 2 класс, если возраст 9 лет, то должны быть доступны 1 класс, 2 класс и 3 класс, если возраст 10 лет или больше, то должны быть доступны все классы от 1 класса до 4 класса. Выбрать можно только один из классов. Для пользователя с одним именем и разными классами должна вестись статистика отдельно по каждому классу, в котором учится пользователь.
    3.4. После ввода имени и выбора класса, пользователь должен нажать кнопку "Начать проверку", после чего должна запуститься проверка умений пользователя по условиям для выбранного класса.
    3.5. Проверка умений пользователя в окне выполняется формированием примера для вычисления - следующим образом: генератор случайных чисел выбирает числа, над которыми выполняется математическое действие, и выбирает математическое действие, которое нужно выполнить (сложение, вычитание, умножение, деление), после этого алгоритм ожидает ввод ответа на заданный пример. Затем в приложении выполняется математическое действие над числами и должен быть получен результат для сравнения, который не должен показываться пользователю до ввода его результата вычисления примера. После ввода ответа пользователя, ответ исправить нельзя. После получения ответа пользователя, ниже должна появиться строка "Правильный ответ", в которой будет показан вычисленный результат для сравнения. Результат вычисления пользователя и результат для сравнения сравниваются: если ответ пользователя равен результату для сравнения, то ниже в дополнительной строке должна появиться оценка "Верно", а если ответ пользователя не равен результату для сравнения, то ниже в дополнительной строке должна появиться оценка "Не правильно".
    3.6. Примеры для вычисления должны отображаться в виде "A + B = C", где "A" - случайное сгенерированное число, "+" - случайное сгенерированное математическое действие, "B" - случайное сгенерированное число, "=" - знак равенства должен обязательно быть показан после сгенерированного примера, после него должно быть поле для ручного ввода ответа пользователя.
    3.7. Визуализация генерации примера для вычисления должна быть выполнена веселой анимацией, интересной детям от 6 до 10 лет.
    3.8. Визуализация оценки "Верно" или "Не правильно" должна быть выполнена крупными анимированными буквами с акцентом на настроении: "Верно" - акцент на веселое, победное настроение; "Не правильно" - акцент на грустное настроение с надеждой, что в другой раз все получится.
    3.9. Следующий пример для вычисления должен начинать генерироваться по кнопке "Следующий пример".
    3.10. Если пользователь хочет завершить сессию, то завершение сессии должно вызываться кнопкой "Закончить проверку". После завершения сессии выставляется оценка за сессию.
    3.11. Для каждой сессии должна вестись статистика, в которой должны быть показаны следующие метрики: общее количество ответов за сессию, количество верных ответов за сессию, количество неверных ответов за сессию, общее количество ответов за класс, количество верных ответов за класс, количество неверных ответов за класс, оценка за текущую сессию, оценка за текущий класс. Статистика должна вестись в отдельном JSON-файле для каждого пользователя. Статистика должна открываться в отдельном окне по кнопке, также кроме текстовых и числовых значений должен формироваться график для визуализации прогресса оценок по количеству сессий (QtCharts).
    3.12. Оценка за сессию выставляется по пятибалльной шкале. Шкала рассчитывается по процентам от количества всех ответов к количеству правильных ответов: оценка "5" - от 95% до 100% правильных ответов, оценка "4" - от 80% до 95% правильных ответов, оценка "3" - от 60% до 80% правильных ответов, оценка "2" - от 40% до 60% правильных ответов, оценка "1" - меньше 40% правильных ответов. Визуализация оценки за сессию должна быть выполнена цифрой оценки за сессию с анимацией акцента на настроении. Акцент для оценки "4" и "5" крупный красный шрифт с эффектом свечения/тени (QSS/QGraphicsDropShadowEffect). Для оценки "5" добавляется визуальный акцент в виде векторной рамки/звезды или эмодзи золотого венка, цифра "3" крупный синий шрифт с объёмной тенью, цифры "1" и "2" строгий плоский тёмно-серый/чёрный шрифт.
    3.13. Оценка за класс рассчитывается как среднее от всех оценок за все сессии в текущем классе, выбранном пользователем.
###4. Ограничения и особенности:
    4.1. Язык приложения - русский.
    4.2. Для примеров 1 класса должны быть доступны только действия сложения и вычитания. Числа для математических действий и результаты математических действий должны находиться в интервале от 0 до 20. Использовать только целые числа.
    4.3. Для примеров 2 класса должны быть доступны действия сложения, вычитания, умножения и деления. Числа для сложения и вычитания и результаты сложения и вычитания должны находиться в интервале от 0 до 100. Числа для деления и умножения и результаты деления и умножения должны находиться в интервале от 1 до 50. До 20% выдаваемых примеров для решения должны содержать от двух до трех математических действий и выражение в скобках с однозначными целыми числами вида "A + (B - C) = D"; "(A x B) + C = D"; "A x (B - C) : D = E"; "A : (B x C) - D = E". Деление на 0 запрещено. Использовать только целые числа. Запрещена генерация примеров для вычисления совпадающих с примерами для вычисления 1 класса.
    4.4. Для примеров 3 класса должны быть доступны действия сложения, вычитания, умножения и деления. Числа для сложения и вычитания и результаты сложения и вычитания должны находиться в интервале от 0 до 1000. Числа для деления и умножения и результаты деления и умножения должны находиться в интервале от 1 до 100. До 20% выдаваемых примеров для решения должны содержать от трех (все числа целые двузначные) до пяти (однозначные и двузначные целые числа) математических действий и выражение в скобках вида "A + (B - C) = D"; "(A x B) + C = D"; "A x (B - C) : D = E"; "A : (B x C) - D = E"; "A + (B + C - D) - E = F"; "A x B +(C : D - E) + F = G", допустимы математические действия между выражениями в скобках (однозначные и двузначные целые числа). Деление на 0 запрещено. Использовать только целые числа. Запрещена генерация примеров для вычисления совпадающих с примерами для вычисления 1 класса и 2 класса.
    4.5. Для примеров 4 класса должны быть доступны действия сложения, вычитания, умножения и деления. Числа для сложения и вычитания и результаты сложения и вычитания должны находиться в интервале от 0 до 1000000. Числа для деления и умножения и результаты деления и умножения должны находиться в интервале от 1 до 1000000. До 20% выдаваемых примеров для решения должны содержать от трех до пяти математических действий и выражение в скобках вида "A + (B - C) = D"; "(A x B) + C = D"; "A x (B - C) : D = E"; "A : (B x C) - D = E"; "A + (B + C - D) - E = F"; "A x B +(C : D - E) + F = G", допустимы математические действия между выражениями в скобках. Во всех вариантах выражение можно использовать двузначные, трехзначные, четырехзначные и пятизначные целые числа. Деление на 0 запрещено. Использовать только целые числа. Запрещена генерация примеров для вычисления совпадающих с примерами для вычисления 1 класса, 2 класса и 3 класса.
    4.6. Для всех классов ВСЕ промежуточные и финальные результаты вычислений должны быть СТРОГО целыми положительными числами (≥0).
    4.7. Деление должно быть строго без остатка.
    4.8. Запрещены отрицательные результаты на любых промежуточных шагах внутри скобок (например, выражение 5 - 8 внутри скобки недопустимо).
    4.9. Ограничение по диапазону классов реализуется через валидацию базовых генераторов: 1 класс (до 20), 2 класс (до 100), 3 класс (до 1000), 4 класс (до 1000000).
